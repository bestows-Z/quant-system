# 实时看盘、板块研究与内容生命周期升级设计

## 1. 目标

本阶段在现有 go-zero 微服务、Python 量化服务、MySQL、Redis、RabbitMQ、Qdrant、Vue 3 和 WebSocket 架构上完成以下升级：

1. 模拟交易严格使用交易时段内的新鲜真实盘口，不使用收盘快照或过期缓存成交。
2. 个股详情采用 A 型专业看盘工作台，实时分时、对比标的、盘口和模拟买卖保持同一上下文。
3. 通知、用户知识库和用户文档具备完整删除与批量清理能力。
4. Agent 将公司资料、近期公告、财经资讯、技术面、资金面和知识库证据纳入同一报告。
5. 板块中心覆盖本地证券主数据可识别的全部行业板块，以及真实数据源可获得的概念板块；提供板块详情、成分股实时行情与板块分时。
6. 个股分时支持最多三个股票或板块作为对比标的。
7. 修复 AI 模型配置页统计块扁长、密集和移动端失衡问题。
8. 收尾五档限价续撮、过期撤单、自动策略评估和定时模拟运行，并更新工程计划和验收文档。

系统仍只执行 paper trading，不接入券商或真实资金。所有策略信号和 Agent 结论仅供研究，不构成投资建议。

## 2. 已确认边界

- 开发环境继续使用免费或低成本公共行情源，不承诺交易所 Level-2 或毫秒级行情。
- 连续竞价时段内，交易使用的最新价与盘口必须不超过 3 秒。
- 下单前必须重新请求一次真实盘口并校验时间、代码、方向和价格。
- 盘口超过 3 秒、时间倒序、来源不是 `real`、盘口为空或处于非交易时段时拒绝委托。
- 休市时允许查看最后有效行情，但买卖按钮禁用，后端仍独立拒单，不能只依赖前端限制。
- 自动交易只发送带盘口保护价格的限价模拟单，不发送无价格保护的市价单。

## 3. 方案选择

采用服务端订阅驱动的实时流，不采用浏览器轮询作为交易依据，也不在本阶段引入 NATS 重建总线。

### 3.1 原因

- 当前 `ws-api` 已具备 JWT、订阅协议、连接管理和 RabbitMQ 事件消费，扩展成本最低。
- 服务端统一采集可以确保页面展示、模拟撮合和自动策略使用同一份带时间戳行情。
- Redis 适合保存最新快照和订阅状态，RabbitMQ继续承载低频业务通知；高频行情不逐条写 MySQL。
- 后续接入合法授权 Level-1/Level-2 Provider 时，只替换 Provider 和流入口，不改变前端及撮合契约。

## 4. 实时行情架构

### 4.1 订阅注册

浏览器通过 `/ws/market` 发送：

```json
{"type":"subscribe","channel":"market","symbol":"688981","feeds":["quote","orderbook","timeshare"]}
```

`ws-api` 维护带引用计数的订阅表。首个订阅者出现时启动该代码的采集，最后一个订阅者离开后延迟 10 秒停止，避免页面切换造成频繁启停。

每个连接最多订阅 30 个股票和 10 个板块；单个分时页面最多展示主标的加三个对比标的。超限返回结构化 WebSocket 错误，不静默丢弃。

### 4.2 服务端采集

新增 `market-stream` 领域组件，第一版位于 `ws-api` 内部并通过 `market-rpc` 获取行情，保持独立接口，后续可拆成单独 RPC：

- 交易时段：每秒采集最新价和五档盘口。
- 分时数据：收到新分钟或累计成交变化时更新，不每秒重拉全天数组。
- 休市时：停止高频采集，仅在首次订阅时返回最后有效快照。
- 同一股票的并发订阅共享一次上游请求。
- Provider 超时和熔断沿用 `market-rpc` 真实多源机制，不生成 mock 数据。

Redis 键：

- `market:stream:quote:{symbol}`，TTL 10 秒。
- `market:stream:orderbook:{symbol}`，TTL 10 秒。
- `market:stream:timeshare:{symbol}:{trade_date}`，保留到下一交易日。
- `market:stream:subscription:{symbol}`，记录引用计数和最后活动时间。

### 4.3 推送契约

每条消息包含：

- `type`：`market.quote`、`market.orderbook` 或 `market.timeshare`。
- `symbol`、`source`、`data_mode`。
- `quote_time`、`server_time`、`latency_ms`、`sequence`。
- 对应快照或增量数据。

客户端按 `sequence` 丢弃倒序事件，并展示“实时、延迟、已停止”状态。页面不得使用浏览器接收时间替代行情时间。

## 5. 模拟撮合与自动交易

### 5.1 新鲜度校验

`paper-rpc` 在事务开始前通过 `market-rpc` 二次获取盘口，并执行：

1. 解析北京时间行情时间。
2. 校验当前时间位于交易日连续竞价时段。
3. 校验行情年龄不超过 3 秒。
4. 校验 `data_mode=real`、买卖五档非空且价格为正。
5. 校验股票代码与请求一致。

任何校验失败返回中文错误、错误码和 TraceID，不创建订单、不冻结资金或持仓。

### 5.2 五档续撮

- 市价模拟单按提交时五档立即成交；可见数量不足的剩余部分取消。
- 限价单按满足价格条件的档位逐档成交，剩余部分保持 `PARTIAL_FILLED` 或 `PENDING`。
- 实时盘口更新后，撮合调度器只扫描该股票的未完成订单。
- 每个档位生成独立成交，保存 `depth_level`、`quote_time`、`data_mode` 和 TraceID。
- 加权成交价由累计成交额除以累计成交数量计算。
- 订单每次续撮均重新校验资金、冻结状态、T+1 可卖数量和价格保护。

### 5.3 过期处理

- 当日限价单默认在 15:00 过期。
- 收盘后调度器撤销剩余数量，释放对应冻结资金或持仓。
- 已成交部分不回滚，状态为 `PARTIAL_FILLED_CANCELED`。
- 撤单和过期事件写入通知中心并通过 WebSocket 推送。

### 5.4 自动策略收尾

- 自动策略版本保持 `SHADOW -> PROMOTED -> RETIRED` 生命周期。
- 晋级前保存回测、样本外区间、最大回撤、胜率、交易次数和数据覆盖率。
- 每个自动账户可启用多个已晋级策略，按风险预算分配资金；总资金仍来源于绑定的模拟账户。
- 收盘后更新候选和策略评估；交易时段按分钟触发增量信号，不让 LLM进入低延迟撮合路径。
- AI 只生成白名单 DSL 参数和解释；量化校验、风控、盘口和 T+1 决定是否执行。

## 6. A 型个股专业工作台

桌面端：

- 顶部：股票名称、代码、最新价、涨跌幅、行情时间、新鲜度和数据源。
- 主区左侧：百分比归一化分时、均价、成交量和最多三个对比标的。
- 主区右侧：五档盘口、盘口时间、买卖数量/金额切换，以及模拟买入和卖出入口。
- 下方标签：K线指标、资金与支撑压力、公司与行业、公告资讯、策略信号、智能分析、持仓影响。

移动端：

- 顶部行情固定为紧凑两行。
- 分时图全宽。
- 盘口、模拟交易和对比设置使用标签或底部抽屉。
- 研究内容保持单标签显示，禁止多个宽表并排。

买卖按钮只有在 WebSocket 已连接、盘口年龄不超过 3 秒且处于交易时段时可用。前端状态仅用于交互提示，后端始终再次校验。

## 7. 分时对比

- 支持通过代码、名称搜索股票，也支持搜索板块。
- 最多添加三个对比标的，重复标的禁用。
- 所有曲线按各自昨收或首个有效基准归一化为涨跌百分比。
- 主股票保留红色，其他标的使用稳定且可区分的蓝、紫、青色，不随刷新改变。
- Tooltip 同时显示时间、各标的涨跌幅、实际价格或板块计算值。
- 对比标的某分钟缺数据时保持断点，不用前值伪造连续成交。

## 8. 板块中心

### 8.1 板块目录

- 行业板块来自完整证券主数据中的行业字段，必须展示全部非空行业。
- 概念板块只展示真实 Provider 成功同步或历史真实缓存中的板块，不使用人工随机成分。
- 每日收盘同步板块与成分关系，盘中只更新行情。

### 8.2 板块行情

板块列表支持按涨跌幅、成交额、上涨家数占比和强度排序。行业板块实时值按成分股流通市值加权；流通市值缺失时使用等权，并明确标记计算方法。概念板块若 Provider 提供官方行情则优先使用，否则按真实成分股计算并标记 `CALCULATED`。

板块分时保存每分钟：

- 加权涨跌幅。
- 上涨、下跌和平盘家数。
- 成交额与成交量。
- 领涨股票及其涨跌幅。
- 数据覆盖率、计算方法和数据时间。

覆盖率低于 80% 时显示数据不足，不输出看似精确的板块曲线。

### 8.3 板块详情

点击板块进入独立详情页，展示板块分时、广度、领涨股和全部成分股。成分股表通过 WebSocket 更新最新价、涨跌幅、成交额、换手率和行情时间，并支持跳转个股详情或加入分时对比。

## 9. Agent 公告与资讯证据

个股分析启动时并行获取：

- 公司资料与行业信息。
- 最近 20 条公开公告。
- 最近 20 条财经媒体资讯。
- 资金流、龙虎榜、技术指标、策略和风险结果。
- Qdrant/MySQL 混合检索片段。

公告与资讯按代码、发布时间和 URL 去重，按发布时间衰减。Agent 上下文只保留标题、时间、来源、摘要和链接，全文通过 RAG 按需检索，避免撑爆上下文。

报告新增“公告与资讯”章节，逐条标记来源和日期，并区分确定事实、媒体报道和模型推断。外部模型不可用时，本地量化报告仍列出公告与资讯证据，不生成情绪结论。报告存档保存所用证据 ID、数据时间和来源状态。

## 10. 内容删除

### 10.1 通知

- 单条删除要求 JWT 与用户归属校验。
- 支持删除全部已读通知。
- 支持清空当前用户全部通知，需二次确认。
- 通知属于短期用户数据，采用物理删除；系统审计事件不存放在通知表。

### 10.2 知识库与文档

- 用户可删除自己创建的文档和知识库。
- 系统公共知识库和系统文档不可由普通用户删除。
- 删除文档采用事务：标记文档删除、删除 MySQL 切块、删除 Qdrant 对应向量。
- Qdrant 暂时失败时记录清理任务并重试，文档立即从查询结果中消失。
- 删除知识库前显示文档与切块数量，确认后级联执行同一流程。
- API 保持幂等，重复删除返回成功和 `already_deleted=true`。

## 11. AI 模型页布局

- 用 Flex 容器承载统计块，允许换行。
- 每个统计块使用 `flex: 1 1 180px`，设置稳定最小高度和最大宽度。
- 数字、名称和说明分层显示，长模型名截断并提供 Tooltip。
- 桌面端每行 3 至 5 个，平板双列，窄屏单列。
- 配置表与调用明细保留自身横向滚动，不撑宽整页。

## 13. 错误处理与可观测性

- 所有 REST 响应保持 `{code,message,data,trace_id}`。
- WebSocket 错误包含 `code`、`message`、`channel`、`symbol` 和 `trace_id`。
- 实时行情指标记录订阅数、上游延迟、推送延迟、过期拒单数、Provider 错误和续撮次数。
- 日志不记录 JWT、API Key、公告全文或模型完整上下文。
- 单个股票或板块采集失败不阻断其他订阅。

## 14. 验收

### 14.1 后端

- Go 执行 `go test ./...` 和 `go build ./...`。
- Python 执行全部 pytest。
- Vue 执行类型检查和生产构建。
- Docker Compose 全量启动，系统健康检查全部 UP。
- 自动验收覆盖实时订阅、3 秒新鲜度、过期拒单、二次盘口校验、限价续撮、收盘撤单和 T+1。
- 删除验收覆盖归属校验、幂等、系统知识保护、MySQL 与 Qdrant 一致性。
- Agent 报告必须包含公告/资讯证据或明确真实数据源不可用状态。
- 板块成分合计、行情覆盖率和分时计算方法可追溯。

### 14.2 前端

- 桌面 `1440x900` 和移动端 `390x844` 无整页横向溢出。
- 个股页 WebSocket 推送后最新价、盘口和分时同步更新。
- 超过 3 秒或休市时买卖按钮禁用，并显示中文原因。
- 分时可添加和删除三个对比标的，颜色与 Tooltip 一致。
- 板块可进入详情并查看完整成分股实时表。
- 通知与用户文档删除后立即从页面消失，刷新后不恢复。
- AI 模型统计块不再扁长或相互挤压。
