# 回测可信度与策略执行内核 V2 设计

## 目标

在不接入真实账户、不改变现有模拟交易产品边界的前提下，修复当前单标的日线回测中的未来函数、成交约束缺失、费用失真、指标口径错误和非原子落库问题。改造后的成功回测必须可解释、可追溯、可重复，并能够明确区分“策略没有信号”“订单无法成交”和“数据不可信”。

## 当前问题

1. 策略读取 T 日收盘价后仍按 T 日收盘价成交，存在同柱成交偏差。
2. 期末强制按最后收盘价卖出，但权益曲线没有同步反映该笔交易，最终资产与曲线末点可能不一致。
3. 胜率只比较买卖价格，没有计入佣金、印花税等费用；盈亏比固定返回 0。
4. 买入数量按可用现金的固定比例估算，没有把最低佣金等成本纳入现金约束。
5. 缺少停牌、涨跌停、最小交易单位、成交量参与率和价格最小变动单位约束。
6. Python API 接收 `adjust=qfq`，但当前路由直接忽略该参数；回测结果也不保存复权证据。
7. Go 回测服务会把非法数字静默替换为默认值；结果、成交和权益曲线分别写库且部分错误被忽略，可能产生不完整的成功记录。
8. 策略只统一检查 30 根 K 线，没有按参数计算真实预热长度；RSI、布林带等路径对 NaN/Inf 的处理不完整。

## 方案选择

### 方案 A：在现有循环上局部修补

改为次日开盘成交并补充费用。改动小，但数据校验、撮合、账本和指标继续耦合在一个函数中，难以证明每一笔资产变化都守恒。

### 方案 B：正确性优先的单标的回测内核 V2（采用）

保持现有 REST/gRPC 入口兼容，Python 内部拆分数据质量、执行规则、费用、账本和指标模块，Go 侧改为强校验和事务化持久化。该方案能够在有限范围内修复核心可信度问题，也为后续多策略组合留下稳定接口。

### 方案 C：完整事件驱动、多标的组合引擎

直接实现订单队列、多标的资金分配和组合再平衡。长期扩展性更强，但超出“第一批先修后端漏洞”的范围，并会与尚未完成的多策略权重阶段耦合。

## 架构

### Python 回测域

- `app/backtest/models.py`：定义不可变的回测配置、订单意图、成交、拒单、持仓和账本快照。
- `app/backtest/data_quality.py`：规范日期与数值类型，排序去重，验证 OHLC、成交量、来源、数据模式和复权方式，输出质量报告。
- `app/backtest/rules.py`：实现 A 股 100 股买入单位、0.01 元价格单位、T+1、停牌、涨跌停和成交量参与率约束。
- `app/backtest/fees.py`：分别计算佣金、最低佣金、卖出印花税和过户费，不再把所有成本折叠成单一费率。
- `app/backtest/metrics.py`：从账本和已闭合交易计算收益、年化收益、最大回撤、胜率、盈亏比、换手率和暴露率。
- `app/backtest/engine.py`：只负责按交易日编排信号、订单、执行、账本和快照。

策略引擎继续保持白名单算法，不允许执行任意代码。每个算法声明自己的最小预热长度；输入不足或指标非有限值时返回有原因的 `HOLD`，而不是产生含 NaN 的证据。

### Go 回测域

Gateway 和现有 backtest-rpc 的对外路径保持不变。请求增加可选的执行配置，旧客户端不传时使用安全默认值。backtest-rpc 在调用 Python 前严格校验股票代码、日期区间、资金、费率、参与率、复权方式、策略编码和 JSON 参数。

Python 返回经过版本化的结果契约。Go 验证 `source`、`data_mode=real`、`adjust=qfq`、`engine_version`、质量状态以及末端资产守恒后，在一个数据库事务中写入结果、成交、拒单和权益曲线，最后才把任务改为 `SUCCESS`。任何一步失败都会回滚结果明细并把任务标记为 `FAILED`。

## 数据与执行流程

1. 获取用户请求区间的前复权日 K；额外获取策略所需预热区间，但绩效只从请求开始日计算。
2. 数据质量门校验必需列、日期单调性、重复日期、有限数值、`low <= open/close <= high`、非负成交量、真实来源和前复权标识。
3. T 日收盘后，用截至 T 日的全部可见数据生成信号，只创建待执行订单，不改变资产。
4. T+1 的第一根有效交易日 K 线到达时，以开盘价作为基准；滑点后的成交价必须位于当日高低价及价格限制内。
5. 停牌或无有效开盘价时拒绝；买入遇到涨停开盘、卖出遇到跌停开盘时拒绝，并保存机器可读原因。
6. 最大成交量为当日成交量乘以参与率，向下取整到 100 股；不足 100 股时拒绝。第一版剩余数量当日取消，不跨日排队。
7. 买入数量同时受目标仓位、可用现金、全部费用和 100 股整数手约束，任何时点现金不得为负。
8. 卖出数量受 T+1 可用持仓约束；本设计的收盘信号、次日开盘执行天然至少间隔一个交易日，同时账本仍显式检查可用日期。
9. 每个交易日收盘按收盘价计价并生成权益快照。期末默认保留持仓并按市值计价，不制造最后一日无法真实执行的强制平仓。

## 安全默认值

- 执行模型：`NEXT_OPEN_V2`
- 复权方式：`qfq`
- 买入单位：100 股
- 价格单位：0.01 元
- 最大成交量参与率：10%
- 目标资金使用率：95%
- 佣金率：0.03%，最低佣金 5 元，买卖双向
- 卖出印花税：0.05%
- 过户费：0.001%，买卖双向
- 滑点率：0.01%
- 期末自动平仓：关闭

费用均为模拟参数，允许用户覆盖并随回测结果保存。交易规则按规则版本解析；缺少证券当时的板块、风险警示或上市状态时，不伪造精确限制，质量报告必须显示规则覆盖不足。2026 年当前规则依据包括[上交所交易规则（2026 年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所交易规则（2026 年修订）](https://www.szse.cn/lawrules/rule/allrules/bussiness/t20260424_620190.html)、[证券交易印花税减半公告](https://shanxi.chinatax.gov.cn/web/detail/sx-11400-545-1780448)和[中国结算上海市场收费表](https://www.chinaclear.cn/zdjs/editor_file/20220701154723234.pdf)。

## 返回契约

结果保留现有 `summary`、`trades` 和 `equity_curve`，新增：

- `engine_version`：固定为 `backtest-v2`。
- `execution_model`：固定为 `NEXT_OPEN_V2`。
- `adjust`：实际使用的复权方式。
- `data_quality`：状态、问题、有效样本数、日期范围、来源和规则覆盖。
- `config`：本次执行使用的完整费用与撮合参数。
- `orders`：包含已成交、部分成交、拒绝和取消状态及原因。
- `summary.realized_pnl`、`unrealized_pnl`、`total_fees`、`turnover_rate`、`exposure_rate`。

现有字段继续保留。金额在 Python 内部使用十进制定点或统一舍入策略，API 序列化为有限数值；Go/MySQL 金额字段继续使用 DECIMAL。

## 错误处理

- 用户参数错误返回 422/InvalidArgument，不创建伪成功任务，也不静默替换默认值。
- 数据源不可用或来源、模式、复权不可验证时，任务失败并保留简洁错误，不保存结果明细。
- 数据质量不满足 OHLC 和有限数值约束时失败；仅规则元数据不足时可以运行，但 `data_quality.status` 为 `PARTIAL`，自动策略评估不得据此晋级。
- 无信号、无成交属于成功回测，返回空成交及明确统计；与系统故障区分。
- Go 事务提交失败时结果、成交、订单和曲线全部回滚，任务不得变为成功。

## 测试设计

### Python 单元与契约测试

- T 日信号只能在 T+1 开盘成交，修改 T+1 收盘价不影响成交价。
- T+1 停牌、买入涨停、卖出跌停分别生成拒单原因。
- 成交量参与率、100 股单位、滑点和价格边界正确。
- 含最低佣金时现金永不为负，买卖费用与印花税方向正确。
- 期末持仓不强平，最终资产严格等于权益曲线末点。
- 胜率和盈亏比基于扣费后的闭合交易；无盈利或无亏损时定义明确。
- 重复日期、乱序、NaN、Inf、非法 OHLC、未知复权和非真实来源被质量门拦截。
- 各策略的参数边界、动态预热长度和非有限指标路径均有测试。
- 旧请求未提供新参数时仍使用安全默认值。

### Go 单元与事务测试

- 非法资金、费率、日期、策略、复权和 JSON 参数返回 InvalidArgument。
- Python 返回非真实、非前复权、未知引擎版本、质量失败或资产不守恒时拒绝保存。
- 任一成交或曲线插入失败时事务回滚且任务不为 SUCCESS。
- 成功结果完整保存版本、配置、质量证据、订单、成交和曲线。

### 回归验证

- Python 全量测试与编译检查。
- Go `go test ./...` 与 `go build ./...`。
- 使用固定小型行情夹具做确定性黄金结果测试。
- Docker 冒烟验证真实数据源回测，并确认返回 `real + qfq + backtest-v2 + NEXT_OPEN_V2`。

## 范围边界

本批不实现多标的组合回测、多策略资金权重、分钟级事件撮合、做空、融资融券、可转债或真实券商连接。多策略组合将在单标的账本和执行契约稳定后单独设计。

## 验收标准

1. 不存在同一根日 K 线生成信号并成交的路径。
2. 每个成功结果都有真实来源、前复权、引擎版本、执行模型和质量报告。
3. 现金、持仓、费用和权益逐日守恒，末端摘要与曲线一致。
4. 所有订单都有最终状态和原因；无法成交不会被当作成交。
5. Go 落库要么完整成功，要么完整回滚。
6. 新增回归测试通过，现有后端测试不回退。
