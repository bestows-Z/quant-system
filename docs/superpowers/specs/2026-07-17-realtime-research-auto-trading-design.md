# 实时研究与智能模拟交易升级设计

## 1. 目标与边界

本阶段在现有量化分析平台上补齐真实行情展示、个股研究资料和智能模拟交易能力：

- 统一北京时间显示，修复当日日 K、分时百分比坐标和 K 线提示信息。
- 市场全景展示上证、深证、沪深 300、科创 50、创业板和北证 50。
- 个股页整合真实盘口、第三方资金流统计、公司资料、官方公告和媒体资讯。
- 新建智能策略生命周期和自动模拟交易服务，默认资金 100 万元。
- 自动订单按真实五档盘口逐档、部分成交，不假设无限流动性。

平台不接真实券商，不执行真实交易。所有候选、信号和报告仅供研究，不构成投资建议。

## 2. 已确认决策

- 个股详情使用 A 型专业看盘工作台：K 线为核心，盘口和资金流位于右侧，资料与公告位于下方标签。
- 分时左轴显示相对昨收百分比，零轴以上红色并带 `+`，以下绿色并带 `-`。
- 自动交易采用多策略组合和“回测、样本外、影子运行、晋级”流程。
- AI 不可用时不生成新策略，只运行已晋级策略。
- 新策略至少完成 20 个交易日影子验证才能晋级。
- 盘口撮合允许部分成交，剩余委托等待后续盘口或超时撤单。
- 公告以巨潮资讯和交易所官方披露为准，财经媒体只作为带来源的辅助信息。

## 3. 真实数据原则

### 3.1 数据模式

所有新增响应必须包含：

- `source`：实际 Provider。
- `data_mode`：`real`、`cache` 或 `unavailable`。
- `quote_time` 或 `published_at`：源数据时间。
- `collected_at`：系统采集时间。
- `is_stale`：是否超过模块时效阈值。

真实源不可用时返回明确不可用状态，不使用推算或 mock 值填充。

### 3.2 数据来源

- 实时行情、分时、盘口：现有腾讯和新浪适配器，多源缓存和熔断。
- 指数行情：腾讯实时指数为主，现有行情 Provider 为备；北证 50 增加北交所或可验证 Provider 适配。
- 公司公告：巨潮资讯、上交所、深交所、北交所公开披露。
- 龙虎榜：巨潮公开信息为主，东方财富为备用。
- 资金流：东方财富 Choice 公开页面对应的第三方统计口径。
- 媒体资讯：可配置的财经媒体 Provider，必须保留来源链接、发布时间和采集时间。

资金流不是交易所逐笔资金身份数据。前端统一显示“第三方统计口径”，不可描述为交易所官方主力或散户数据。

## 4. 服务架构

### 4.1 market-rpc

扩展职责：

- 六大指数实时行情。
- 当日日 K 合成。
- 东方财富资金流适配。
- 公司资料和官方公告查询。
- 龙虎榜采集与查询。
- 媒体资讯查询。

所有外部调用必须经过 Provider Client，业务逻辑不得直接使用 `http.Get`。

### 4.2 feature-rpc

扩展职责：

- 市场层级涨跌、成交额和市场宽度。
- 资金流、公告事件和市场状态因子。
- 多策略风险预算和股票可交易性过滤。
- 因子版本、覆盖率、置信度和证据记录。

### 4.3 auto-trader-rpc

新增独立 go-zero RPC 服务：

- 自动策略账户和运行配置。
- AI 候选策略生成。
- 策略 DSL 校验与版本管理。
- 回测、Walk-forward 和压力测试编排。
- 影子运行、晋级、暂停和退役。
- 多策略资金与风险预算。
- 调用 paper-rpc 下单。
- 自动交易运行记录和审计。

### 4.4 paper-rpc

扩展撮合能力：

- 保存订单的已成交量、剩余量和加权成交价。
- 按盘口档位生成多条成交记录。
- 行情更新后继续撮合部分成交订单。
- 支持订单有效期和自动超时撤销。
- 没有盘口时拒绝自动市价单。

## 5. 时间格式

- 数据库存储 UTC 或带时区时间。
- API 继续返回 RFC3339，保证机器可解析性。
- 前端统一通过 `formatDateTime` 转换为 `Asia/Shanghai`，显示 `YYYY-MM-DD HH:mm:ss`。
- 表格、通知、任务、公告、成交和策略报告不得直接输出包含 `T` 或 `Z` 的原始时间。
- 仅日期字段显示 `YYYY-MM-DD`。

## 6. 当日日 K 合成

当正式日 K 未包含当前交易日时，由 market-rpc 生成一根临时日 K：

- `open`：当日分时第一笔有效价格或实时开盘价。
- `high`：分时和实时最高价的最大值。
- `low`：分时和实时最低价的最小值。
- `close`：最新价。
- `volume`、`amount`：实时累计成交量和成交额。
- `trade_date`：当前 A 股交易日。
- `is_realtime_bar=true`，`bar_status=INTRADAY`。

前复权图使用上一交易日前复权收盘价与实时昨收的比值作为临时调整因子，对盘中 OHLC 做一致调整。成交量和成交额不复权。

收盘后，正式 Provider 日 K 覆盖临时 K 线。同一股票、周期和交易日只能返回一根 K 线。

非交易日、停牌或无有效成交时不合成当日 K 线。

## 7. 图表交互

### 7.1 分时

- 左侧主轴只显示相对昨收涨跌幅。
- 轴范围以零轴对称，最大绝对幅度至少 0.5%。
- 正值使用红色和 `+`，负值使用绿色和 `-`，零值使用中性色。
- 悬浮显示时间、涨跌幅、价格、均价、分钟成交量和分钟成交额。
- 上午和下午交易时段保持连续布局，午休位置明确标注。

### 7.2 K 线

- MA5、MA10、MA20、MA60 使用固定颜色常量，图例、曲线和悬浮值共享同一配置。
- 悬浮显示日期、盘中状态、涨跌幅、开高低收、成交量、成交额和所有可用均线。
- 涨跌幅按上一根 K 线收盘价计算。
- Tooltip 使用 `confine` 和动态定位：高位蜡烛显示在下方，低位蜡烛显示在上方。
- 盘中 K 线增加视觉标记，避免用户误认为正式收盘数据。

## 9. 个股详情工作台

第一屏：

- 股票名称、代码、实时价格、涨跌幅、成交量额、换手率、数据源和更新时间。
- 模拟买入、模拟卖出、添加自选和智能分析操作。
- 左侧 K 线与成交量，右侧五档盘口和真实资金流。

第二层标签：

- 技术指标：MACD、RSI、KDJ、BOLL。
- 策略与风险：非零策略信号、风险等级、支撑压力。
- 公司概况：行业、地区、上市日期、主营业务、公司简介。
- 官方公告：标题、类型、发布时间、官方链接。
- 媒体资讯：来源、标题、发布时间、原文链接、可信度标签。
- 持仓影响：真实持仓和模拟持仓中的组合暴露。

资金流展示主力、超大单、大单、中单和小单净流入及占比。数据不可用时整个资金流内容区显示原因，不显示零值占位。

## 10. 龙虎榜

- 每个交易日收盘后采集。
- 保存股票、上榜原因、买入额、卖出额、净买额、总成交额、交易日和来源。
- Provider 失败时保留上一次成功日期并显示数据新鲜度。
- 页面默认展示最近有效交易日，而不是固定查询自然日。
- 不使用模拟记录填充空表。

## 11. AI 策略 DSL

AI 只能生成 JSON DSL，不执行任意代码。DSL 包含：

- 策略名称、版本、适用市场状态。
- 因子和固定白名单算子。
- 开仓、减仓、平仓条件。
- 最大持仓、单票权重和调仓频率。
- 止损、止盈、最大回撤和流动性条件。
- 生成依据和模型配置引用。

服务端执行 JSON Schema、算子白名单、参数范围和复杂度校验。校验失败的候选不得进入回测。

## 12. 策略生命周期

状态流：

`DRAFT -> BACKTESTING -> OUT_OF_SAMPLE -> SHADOW -> PROMOTED -> PAUSED -> RETIRED`

每日收盘后：

1. 汇总行情、因子、公告事件和当前策略绩效。
2. AI 生成新候选或参数调整候选。
3. 回测并计入手续费、印花税和滑点。
4. 执行 Walk-forward 样本外验证和参数扰动测试。
5. 合格候选进入影子运行。
6. 影子运行满 20 个交易日且达到门槛后自动晋级。
7. 已晋级策略发生风险越界时自动暂停，不等待 AI 决定。

每日允许产生新版本，但新版本必须重新走验证流程，不能覆盖正在运行的稳定版本。

## 13. 多策略组合与风控

默认自动模拟账户初始资金为 1,000,000 元。

默认限制：

- 单票目标权重不超过 10%。
- 单策略风险预算不超过 35%。
- 单行业目标权重不超过 30%。
- 单日账户亏损达到 2% 时停止新开仓。
- 账户最大回撤达到 8% 时暂停全部自动策略。
- 可用现金保留比例不低于 10%。

股票池覆盖完整 A 股，但自动排除：

- 停牌、退市整理和缺少真实行情的股票。
- 无真实盘口且策略请求市价单的股票。
- 近期成交额低于流动性阈值的股票。
- 涨跌停导致无法按价格保护成交的股票。

ST 和上市初期证券由规则配置控制，默认不允许自动开仓。

## 14. 五档盘口撮合

### 14.1 市价买入

从卖一到卖五依次成交：

`fill_i = min(remaining_qty, ask_volume_i)`

成交金额：

`gross_amount = sum(fill_i * ask_price_i)`

加权成交价：

`average_fill_price = gross_amount / filled_qty`

### 14.2 市价卖出

从买一到买五依次成交，公式与买入相同，并受 `available_volume` 和 T+1 限制。

### 14.3 限价订单

- 限价买入只消费价格小于等于委托价的卖盘档位。
- 限价卖出只消费价格大于等于委托价的买盘档位。
- 每档成交量不能超过可见盘口量。

### 14.4 部分成交

- `filled_volume` 记录累计成交数量。
- `remaining_volume` 记录剩余数量。
- 状态使用 `PARTIAL_FILLED`。
- 后续盘口更新继续尝试撮合。
- 超过 `expire_at` 后剩余数量自动撤销，已成交部分不回滚。
- 每个档位生成独立 paper_trade，订单保存总加权成交价。

自动策略没有真实盘口时禁止市价单，只允许带 `limit_price` 和最大滑点保护的限价单。

## 17. 错误处理

- 单个外部 Provider 失败不影响其他独立模块。
- 错误响应包含 `code`、`message`、`data` 和 `trace_id`。
- 资金流、公告和媒体资讯分别显示数据源状态。
- AI 调用失败不会中断已晋级策略，也不会生成空策略。
- 盘口过期、缺失或时间倒序时拒绝自动撮合。
- 数据源错误、策略校验失败和风控拒绝均写入审计记录。

## 18. 验收

### 后端

- Go 执行 `go test ./...` 和 `go build ./...`。
- Python 执行全部 pytest。
- Docker Compose 全量启动，系统健康检查全部 UP。
- 自动验收覆盖指数、当日 K 线、公司资料、公告、龙虎榜和资金流可用/不可用语义。
- 撮合测试覆盖五档全部成交、部分成交、多次续撮、限价保护、超时撤单、无盘口拒绝和 T+1。
- AI 策略测试覆盖 DSL 拒绝、回测、影子运行、晋级、暂停和模型不可用。

### 前端

- 时间页面不出现原始 `T` 或 `Z`。
- 当日交易时段 K 线包含唯一的盘中日 K。
- 分时百分比轴、颜色和符号符合设计。
- K 线 Tooltip 在最高与最低蜡烛均不被裁切。
- 桌面 `1440x900` 和移动端 `390x844` 无整页横向溢出。
- 资金流不可用时不显示伪造零值。
- 公告和媒体资讯来源清晰可区分。
